# IoT-23 cleaned data

Generated by `scripts/clean_iot23.py` from the `conn.log.labeled` Zeek logs of 23 IoT-23 scenarios (the `iot_23_datasets_small` release, labelled Zeek flows only). Section 0 of `Lab3.ipynb` runs the same steps.
Output: `iot23_clean.parquet` (717,667 rows, 54 features + `scenario`, `malware`, `detailed_label`, `family`, `is_attack`).

Load with `pd.read_parquet("iot23_clean.parquet")`. Features are `[c for c in df.columns if c not in ['scenario', 'malware', 'detailed_label', 'family', 'is_attack']]`;
the target is `is_attack` (0 = Benign, 1 = Malicious).

## Cleaning steps

| Step | Rows | Removed |
|---|---:|---:|
| raw flows (all scenarios) | 325,309,946 |  |
| sample of distinct flows, ≤ 50,000 per (scenario, detailed label) | 721,493 | 324,588,453 |
| after dropping duplicate rows across scenarios | 718,029 | 3,464 |
| after dropping ambiguous-label rows | 717,667 | 362 |

- Kept Zeek fields: `id.orig_p`, `id.resp_p`, `duration`, `orig_bytes`, `resp_bytes`, `missed_bytes`, `orig_pkts`, `orig_ip_bytes`, `resp_pkts`, `resp_ip_bytes`, `proto`, `service`, `conn_state`, `history`. Dropped: `ts`, `uid`, `id.orig_h`, `id.resp_h` (identifiers: the IPs name the capture, not the behaviour), `local_orig`, `local_resp` (always unset), `tunnel_parents`.
- Sampling: within each (scenario, detailed label) group, flows whose 14 fields are identical count once, and at most 50,000 distinct flows are kept, chosen uniformly at random (the ones with the smallest hash, so the choice is reproducible). Groups below the cap are kept whole, so rare labels and the honeypot captures are complete. The cap changes the class balance: raw IoT-23 is ≈90% Malicious, mostly scan and flood copies.
- Unset values (`-`) filled with 0: `duration` 290,329, `orig_bytes` 290,329, `resp_bytes` 290,329 rows.
- Encoding: `proto_*`, `service_*`, `conn_state_*` are one-hot (`none` = Zeek's `-`). `history_orig_*` / `history_resp_*` are 1 if the originator / responder flag letter appears in Zeek's `history` string (S=SYN, H=SYN-ACK, A=ACK, D=data, F=FIN, R=RST, C=bad checksum, G=gap, I=inconsistent, Q=multi-flag, T=retransmission, W=zero window); `history_FLIPPED` is the `^` flag.
- Ambiguous labels: 181 feature vectors carried more than one detailed label (174 of them Benign vs an attack). All copies are removed, so every remaining feature vector appears once with one label (no identical rows can land in both train and test).
- Dropped constant columns: `history_resp_SYN`, `history_resp_INCONSISTENT`, `history_orig_MULTIFLAG`, `history_resp_MULTIFLAG`.
- Not done here: scaling (most numeric columns are heavy-tailed; `log1p` works well), train/test split, device partitioning.

|---|---:|

| C&C-PartOfAHorizontalPortScan vs PartOfAHorizontalPortScan | 7 |
| Attack vs Benign | 1 |
